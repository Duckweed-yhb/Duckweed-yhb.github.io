这是GitHub仓库管理实操笔记，主要记录私有仓库转为公开仓库时的历史提交泄露风险，以及清除提交历史只保留当前文件的完整操作流程。

### 笔记内容概览
- **核心风险结论**：仅修改仓库公开权限不会清除Git历史，已删除的隐私文件依然可被查看
- **适用场景**：需要对外公开代码，但希望抹除全部过往提交历史，只保留当前版本文件
- **前置准备工作**：仓库备份、处理未提交修改、关闭分支保护
- **完整操作流程**：GitHub Desktop搭配终端清除历史全套命令
- **风险提示**：密钥、证件、隐私信息会留存于旧提交快照，直接公开会造成信息泄露

### 完整操作
#### 核心结论
私有仓库切换为公开仓库**仅仅修改访问权限**，**不会删除任何Git历史记录**。
所有人可以查看：
- 全部提交记录
- 所有历史版本文件
- 曾经上传、后续又删除的内容

> 重点风险：就算你后续在新版本删除密钥、证件、隐私文件，旧提交快照依然永久保留。一旦公开，敏感信息直接泄露。

#### 需求场景
只想公开最新代码，**清除所有过往提交历史**，仅保留当前文件。
GitHub Desktop 没有图形化按钮，配合内置终端即可完成。

#### ⚠️ 前置操作【必做】
1. 完整备份仓库（下载归档 / 复制本地文件夹）
2. 确保本地没有未提交的改动
3. 网页端临时关闭 main 分支保护规则，否则强制推送失败

#### 操作步骤
1. GitHub Desktop 选中目标仓库，切换到主分支(main)
2. 顶部菜单 `Repository → Open in Terminal`
3. 依次执行命令
```bash
# 创建无历史孤儿分支
git checkout --orphan new-clean
# 暂存当前所有文件
git add .
# 创建全新初始提交
git commit -m "Initial commit (clean history)"
# 删除旧主分支
git branch -D main
# 重命名分支为主分支
git branch -m main
