# Agent 面试到底在考什么：读 Joye 的实习面试修炼手册

## 前言

本文整理自 Joye 在 2026-03-09 发布的[《一个大二实习生的 Agent 开发面试修炼手册》](https://www.joyehuang.me/blog/20260309---agentinterview/post)。

作者背景交代得很清楚：墨尔本大学大二、计算与软件工程在读，此前在上海特赞（Tezign）做 AIGC 研发实习，负责 Atypica——一个商业研究方向的 Multi-Agent 系统；写这篇文章时他正在看新机会，陆续面了近 10 家公司，清一色是 AI 创业公司和海外 Startup，方向集中在 Agent 开发与 LLM 应用工程。

他的核心判断是：**Agent 岗的面试经验在中文互联网上还很稀缺，因为它没有八股可背——面试更像一场关于“你到底理不理解你在做的东西”的深度对话。**

以下按原文脉络条理化整理，观点与细节归原作者。

---

## 一、为什么 Agent 面试没有八股可背

原文给出的类比很直接：前端八股你背完可能一辈子用不上，但 Agent 面试里被问到的这些问题，是你在做项目时**真真切切需要去做的设计决策**。

- “上下文爆了怎么办”不是一道面试题，它是你的 Agent 跑到第 20 轮对话时一定会遇到的工程问题
- “如何防止 LLM 乱用 Tools”也不是面试官在刁难你，它是你部署到生产环境后第一周就会收到的 bug report

反过来推：如果你在自己的项目里已经认真做过上下文工程、做过 Tool-Calling 的可靠性保障、思考过 Prompt 注入的防御，那么这些就不是需要“准备”的面试题，而是**可以直接讲出来的实战经验**——这才是真正的加分项。

面试官关心的东西大致分三个层次，越往后越难准备，也越能体现工程成熟度：

| 层次 | 面试官在看什么 | 典型问题 |
|---|---|---|
| 会不会用 | 工具与框架的实操经验 | 用过 LangChain 吗？RAG 怎么搭的？MCP Server 怎么设计？ |
| 理不理解为什么这样设计 | 对设计取舍的理解 | 为什么结构化 Prompt 效果更好？为什么要做记忆分层？为什么选 Vercel AI SDK？ |
| 能不能在工程约束下取舍 | 判断力 | Token 预算有限怎么办？速度和质量怎么平衡？幻觉怎么兜底？ |

---

## 二、面试题全景：七个主题

原文把这段时间遇到的题目按主题做了分类，这份清单本身就很适合当复习目录：

| 主题 | 被问到的点 |
|---|---|
| RAG 与检索增强 | 多重 RAG 与单一 RAG 的区别与适用场景；检索增强怎么做；什么时候用向量检索、什么时候用图数据库；数据清洗；RAG → Agentic Search → Agentic Memory 的演进路径 |
| Agent 架构与编排 | 路由设计（怎么决定调用哪个 Sub-Agent）；兜底机制；Sub-Agent 并行还是异步、能不能互相通信；防止 LLM 乱用 Tools；死循环调用怎么处理；MCP Server 设计；整体框架；回调（Callback）机制 |
| 上下文工程与 Token 管理 | 怎么省 Token；上下文爆了怎么办（除了 FIFO）；短期记忆如何转成长期记忆；提示词压缩；Prompt Cache 打在哪些位置 |
| Prompt Engineering 与安全 | 结构化 Prompt 为什么提升质量；隐晦情感 CoT 怎么设计；怎么防恶意注入；抽象需求如何转化为实际需求；访谈开始/结束有没有做注入防护；One-shot 的负面作用（example 不够差异化会限制模型思路） |
| LLM 基础与模型工程 | Attention 机制；Pretrain 与 LoRA 微调；LLM as a Judge 的设计与局限；速度与质量的取舍；如何避免 OOC（Out of Character）；幻觉处理 |
| AI Infra 与工程化 | 模型网关 / Agent 网关的设计；Eval 平台搭建；DPO / APO 算法评估；为什么使用 Vercel AI SDK |
| 行业认知与系统设计 | Manus / OpenClaw / OpenCode 的架构设计；Agent 的主要应用场景；Skill 与 MCP 的关系；LangChain / LangGraph 的使用经验 |

原作者的一句话总结：**这些问题没有一个可以靠“背”来解决。**

## 三、六个真正让人成长的问题

原文没有逐题给“参考答案”，而是挑出六个当场答得顺、或者没答好的问题，讲它们背后真正的工程直觉。

**1. 上下文爆了怎么办？除了先进先出还有什么？**

几乎每家都问，而且面试官不满足于“FIFO 淘汰最早的消息”。他的追问是：如果用户在对话开头说了一个非常重要的约束条件，你用 FIFO 直接把它丢了怎么办？

作者复盘时意识到，这题考的是**上下文工程的全局视野**。他在 Atypica 里其实已经在做记忆分层（Working / Short-term / Long-term）、摘要压缩、检索拼接、Token Budget 管控，但没有把它们串成一条完整的 Pipeline 来讲。

由此得出的教训是全文最值钱的一句：**做过不等于能讲清楚。** 之后他开始刻意用“问题 → 方案 → 权衡 → 结果”的框架，重新梳理项目里的每一个设计决策。

**2. 如何防止 LLM 乱用 Tools？**

“加个权限控制”远不够。Atypica 里搭了一套 Tool-Calling 的异步状态机：checkpoint、重试、幂等、超时回滚、状态恢复；进入死循环反复调同一个工具时，还有 watermark、去重与断点续跑。

但面试官点出更关键的一层：**与其在运行时做这么多防御，不如在 Prompt 层面就把工具的使用边界讲清楚。** 很多 Agent 可靠性问题的根源不在 Runtime 层，而在 Prompt 层——指令本身含糊，再多的工程兜底也只是在给糟糕的 Prompt 擦屁股。

**3. 为什么结构化 Prompt 比自然语言 Prompt 效果更好？**

作者原本的答案是“结构化信息更容易被模型解析”，面试官追问：“从 Attention 机制的角度，你能解释一下为什么吗？”

面试官给的思路是：用 XML 标签、JSON Schema 或明确分隔符的结构化 Prompt，实际上是在**帮助模型的注意力分配**——让关键信息在 token 序列里有更清晰的“锚点”，降低模型在长上下文里“找重点”的难度；而自然语言表述往往把关键信息淹没在修饰语和过渡句里。

结论：工程层面做的 Prompt 优化，背后有扎实的模型机制支撑。**知其然更要知其所以然**，面试官能很快分辨出你是“背的经验”还是“真的理解了”。

**4. 如何把抽象需求转化为实际需求？**

面试官的原话大概是：“用户说‘让 AI 更聪明一点、更有活人感一点’，你怎么把这种模糊需求变成可落地的技术方案？”

Atypica 里的做法是一套 Counter-Questioning（澄清式反问）系统：需求模糊时，Agent 不硬猜，而是通过显式与隐式的意图识别，把模糊需求拆成结构化约束——目标、受众、风格偏好、限制条件。

作者讲完这套设计后，被反问了一个他答不上来的问题：“那你怎么评判 Counter-Questioning 的质量？怎么知道你问的问题有效，而不是在浪费用户耐心？”他后来想到的方向是 LLM as a Judge 或用户满意度的间接指标，但没有深入实践过。**面试会精准地戳到你知识体系的边界。**

**5. 如何防止 Prompt 恶意注入？**

他当场只答了输入过滤、角色锁定、输出校验这类基础思路。面试之后去补课，发现这个领域有两条很清晰的核心思想：

- **OpenAI 的 Instruction Hierarchy（指令层级）**：给不同来源的指令设定优先级——System Prompt > 开发者指令 > 用户输入，让模型在遇到冲突指令时知道该听谁的
- **Anthropic 的沙盒化思路**：把不可信的外部内容隔离在受限的执行环境里，从架构层面限制恶意指令的影响范围

他的建议是：做 Agent 开发的人都该去读 OpenAI 和 Anthropic 的技术博客——不是停留在理论的论文，而是一线的工程实践建议。当然论文也值得读。

**6. 你了解 Manus / OpenClaw / OpenCode 的设计吗？**

这不是技术深度题，而是**行业广度**题：你有没有在关注行业正在发生什么，而不只是埋头在自己的项目里。

作者当时对 Manus 和 OpenCode 有些了解（研究过 OpenCode 的架构），但对 OpenClaw 了解不多，答得比较勉强。这件事之后他养成了一个习惯：每周固定时间看这些项目的 changelog 和 design doc，不一定要深入，但至少知道风向往哪吹。

## 四、比刷题更重要的事

**复盘是面试最大的杠杆。** 不做复盘的面试没有意义。条件允许就录音；不允许就在面试结束后立刻找地方坐下来，趁记忆热乎把所有问题和自己的回答记下来——**尤其没答上来和答得磕巴的那些**，它们才是最有价值的素材。原文里那份面试题清单就是这么一轮轮记下来的。

**主动让面试官给你复盘。** 反问环节有两个值得问的问题：“我今天哪里表现得不太好、需要改进？”“我哪里做得还不错？”大部分面试官都愿意回答，反馈比你自己瞎猜精准得多，同时也展示了你在积极寻求成长。除此之外还可以问“如果入职，第一个要上手的项目是什么”——既显诚意，也能判断岗位实际内容和 JD 是否一致。

**面试官也是你的人脉。** 面完不管结果如何，尽量加个微信或 LinkedIn。原文给了一个真实案例：面了一家做 toB 方向的 Fintech Agent 公司，通过了一面，但面试官觉得那家公司的方向和他的兴趣不太匹配，**主动把他推荐给了另一家公司**——你现在看到的那次“没成功”的面试，可能正是下一段的起点。

关于选 Offer，原文给了几条很实用的建议：

- **用一个问题筛掉不靠谱的创业公司**：反问环节一定问“对比竞品，你们产品的核心优势是什么？”如果面试官连自家产品的差异化都讲不清楚，方向大概率是模糊的
- **不要被“天使轮融资 xxx 万”忽悠**：融资只是一个维度，还要看产品方向、团队背景、能不能学到东西、有没有人带你；实习是学习投资，不是单纯卖时间
- **不要被“全职”标签吓退**：岗位写全职也可以主动联系，说明自己还在读书但希望有实习机会；最坏不过被拒，很多公司其实有实习 headcount 只是没单独发出来。作者的实习经历足够扎实，甚至去面了一个全职 Agent 开发岗并通过了——面试官到最后才发现他还没毕业。**不要自我设限，别人对你的预期往往没有你对自己的预期那么低。**

## 五、从面试题看行业风向

面试官问什么，某种程度上反映了行业当下最关心什么。原文总结了五条：

1. **RAG 正在向 Agentic 方向演进**——几乎没有面试只停留在“检索 + 生成”的基础层面，大家关心的是 Agentic Search 与 Agentic Memory：检索不再是被动管道，而是 Agent 自己决定什么时候搜、搜什么、结果怎么用
2. **三大落地场景反复被提及**——AI 搜索（关键词匹配到语义理解）、Chat-to-BI（自然语言生成数据分析图表）、Vibe Coding（AI 辅助甚至主导代码编写）
3. **AI Infra 层开始被认真对待**——模型网关怎么设计、Agent 网关怎么做路由和限流、Eval 平台怎么搭、DPO/APO 了解多少；行业正从 demo 阶段走向生产级
4. **MCP 与 Skill 体系正在标准化**——未来 Agent 开发可能不再是从零搭建，而是在一个标准化的能力市场里做组装与编排
5. **工具链选型体现工程品味**——“为什么用 Vercel AI SDK 而不是 LangChain”考的是你对生态的理解和判断力；能讲清楚“为什么选它、trade-off 是什么、什么场景会换别的”，比“我用过 xxx”有说服力得多

## 六、自检清单

把原文的要点压成一份可以逐条过的清单：

- [ ] 我能把项目里的设计决策讲成“问题 → 方案 → 权衡 → 结果”吗？（做过 ≠ 讲得清楚）
- [ ] 上下文爆掉时，除了 FIFO 我能说出几种方案？（分层记忆、摘要压缩、检索拼接、Token 预算）
- [ ] 我的工具使用边界是**写在 Prompt 里**，还是只在运行时兜底？
- [ ] 我能从注意力机制的角度解释结构化 Prompt 为什么更有效吗？
- [ ] 我知道 Prompt 注入防御的两条路线吗？（指令层级 / 沙盒化）
- [ ] 抽象需求进来时，我有澄清式反问的机制吗？反问质量又怎么评估？
- [ ] 我有关注 Manus / OpenCode / OpenClaw 这类项目的 changelog 与 design doc 吗？
- [ ] 每次面试后我做复盘了吗？有没有主动向面试官要反馈？

原文最后一句值得抄下来：**从“我在项目里用过 Agent”到“我能设计一个可靠的 Agent 系统”，中间隔着的不是更多的项目经验，而是更深的理解和更系统的思考。**
