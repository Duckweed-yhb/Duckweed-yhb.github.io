# 挖洞进入“许愿时代”：读 Hacking with LLMs

## 前言

[彭志亮](https://github.com/edwardzpeng)（zhiniangpeng）是知名安全研究员，这本《[A Year of Hacking with LLMs](https://sites.google.com/site/zhiniangpeng/blogs/Hacking-with-LLMs)》是他关于“过去一年用 LLM 做安全研究”的总结，也是他在网络安全会议 OffbyOne 2026 上演讲的文字版。

这篇文章读起来非常“吓人”：2023 年他第一次用 LLM 挖漏洞，几乎失败；2026 年，他在真实设备上批量确认了几百个漏洞，单个 PoC 的成本不到 1 美元，甚至说出了“SOTA 模型只需要对它许愿，就能找到漏洞”这种话。一年之内发生了什么？这篇笔记尝试把故事完整捋一遍。

---

## 一、2023 年的失败：把挖洞当成分类题

故事开始于 2023 年。想法很直接：LLM 能理解代码，那给它看足够多的漏洞代码，它就应该能判断一段代码有没有漏洞。

他们的做法是：收集约 **4 万个 Python 漏洞样本、3.7 万个 Java 漏洞样本、4 万个正常样本**，用它们微调 Code Llama，目标是输入一段代码，输出“有漏洞（具体漏洞）”或“没有漏洞”。

Benchmark 上表现很好：24 类测试里 8 类拿到 100%，23 类超过 90%。然后拿去测真实代码——**几乎没有用**。输出很“吵”：大量看起来像漏洞、实际无法利用的结果，无法行动，也无法验证。

复盘出七条教训：

| 教训 | 说明 |
|------|------|
| 目标错了 | 识别漏洞模式 ≠ 漏洞研究的过程 |
| 能力错了 | 更多 SFT 数据 ≠ 更深的推理能力 |
| 过拟合 CVE 模式 | CVE 里常见的代码特征 ≠ 系统真正要维护的安全不变量 |
| 上下文不够 | 一段代码片段 ≠ 目标系统的完整上下文 |
| 没有威胁模型 | 没有安全边界、敌手能力、入口点，就无法判断行为是否真是漏洞 |
| 无法验证 | 模型不能自己运行、调试和验证判断 |
| 没有持续研究 | 一次问答不是研究，研究需要“假设—证据—修正”的循环 |

一句话总结：**他们当时把漏洞挖掘当成了一个分类问题。**

---

## 二、2025 年底：Agent 上真机，110 个漏洞

两年之后，四件事变了：

1. **模型变强了**：GPT-5.2、Opus 4.5 这一代模型有了真正的推理能力；
2. **上下文变长了**：整个代码仓库、调用链、信任边界都能放进上下文；
3. **Agent 工作流成熟了**：ReAct、Plan-and-Execute、Multi-Agent 让模型能拆解任务、根据中间结果继续调整；
4. **工具变多了**：MCP、CLI、A2A、Skill，模型可以真正“动手”，而不是在聊天框里给答案。

> 真正的突破不只是模型更强，而是模型周围的系统变得更完整了。

于是有了第二次尝试：**用 LLM + Agent 挖 Android 定制系统的访问控制漏洞**（与 X0ev、昆仑实验室的 Wh1tc 合作）。场景很典型——如今的 Android 生态不只有手机，还有手表、手环、电视、车机和各种 IoT 设备，厂商在 ROM 里塞了大量高权限的 OEM Service，向普通 App 暴露接口，而权限验证在复杂的定制代码中经常出现缺口。

关键设计是**不直接让模型“读固件找漏洞”**，而是先准备一套确定性工具：

- Firmware Unpacking：从 system、vendor、product 分区提取 APK；
- JADX 反编译：把系统 APK 转成可读的 Java 代码；
- Manifest Scan：整理 permission、action、component；
- Indexing / Task Generation：索引代码、筛选高风险导出组件；
- ADB 与 Logcat：调用真实接口并收集访问控制证据。

工具是确定性的，Skill 决定 Agent 什么时候、以什么顺序使用工具。对高风险 API 让 Agent 做两步推理：

1. **理解行为**：什么身份、参数和系统状态会触发敏感操作？
2. **判断授权**：这个操作是否超出了调用者应有的权限？

这两个问题把“看起来像漏洞”和“真正违反安全边界”区分开了。候选漏洞还要在**真实设备**上跑 PoC 验证，失败就根据日志修改重试。

最终用 Codex GPT-5.2 Extra High，在 OPPO、HONOR、小米、三星和 Google 的真机上：

- **110 个确认漏洞、183 份报告**；
- **每个 PoC 平均成本不到 1 美元**；
- 每个 PoC 平均只需约 2 次迭代。

分工变成了：**AI 用工具执行范围明确的分析并生成报告；研究员选择攻击面、搭建 harness 和 skill、判断结果价值、对最终结论负责**。这是“研究员 & AI 共同做研究”。

## 三、Diffract：漏洞挖掘变成 token 经济学

下一步：连“选择攻击面、构建 harness”也交给 AI 行不行？如果有足够的**补丁、公开 write-up 和 PoC**，答案开始变成“可以”。

他们构建了 **Diffract**（与 Yunpeng Tian、@___2st 合作），流程是一个能积累知识的闭环：

```
收集公开 write-up/PoC → 建知识库和 skill → 分析 patch diff
→ 提取 root cause → 沉淀漏洞 pattern → 搜索 variants
→ 构建 PoC → 结果回灌知识库
```

在 Microsoft Windows 内核与高权限服务上，用 Claude Opus 4.6 到 4.8 跑出了 **200+ 确认漏洞、400+ 报告**，覆盖 RCE、LPE 和信息泄露。作者直言：Windows 漏洞研究在 2026 年“变得相当无聊了”——MSRC 已经非常努力，9 月一个月就修复了接近 1000 个漏洞。

对 2026 年的现状，他给出一个三段论：

- **上一代模型 + 够好的 harness**：GPT-5.2、GLM-5.2 就能挖出很多漏洞；
- **够好的模型**：Opus 4.6、Kimi k3、DeepSeek v4、GPT 5.4、GLM 5.3，接近全自动；
- **SOTA 模型**：“只需要对模型许愿，就能找到漏洞，已经毫无门槛。”

这三个跃迁，**在半年内完成**。漏洞挖掘的主导成本从“研究员的时间”变成了“模型能力 × token × 工具 × 算力”——一种 token 经济学：短期内只要你烧得起更多 token，就能找到更多漏洞，因为历史遗留漏洞实在太多了。

那“许愿”的极限在哪？作者举了个例子：

> /goal 给我一个 iOS 0-Click fullchain RCE exploit

用 200 美金的 SOTA 订阅大概率做不到。但如果是 OpenAI 的内部模型、1 万个 agent 协作 88 小时（OpenAI 用来解决 NS 方程千禧年难题的资源配置）呢？——这个差值，后面还会提到。

## 四、密码学：20 分钟攻破四年

彭志亮读的是密码学博士，2013 到 2017 年做了四年密码学研究，但从没攻破过一个真正强的密码系统，2017 年转做真实系统攻防，“原因很简单：数学对我来说太难了”。

于是他想：AI 能不能帮我成为真正的 codebreaker？

第一个测试对象是他自己设计的一个**从未发表的 attribute-based signcryption 方案**——这个方案的安全证明他自己做了四年都没完成。他把它交给 GPT-5.6，请它证明方案安全。

**大约 20 分钟后**，GPT 告诉他这个方案为什么**不可能**被证明安全：它找到了一个具体攻击。

> 看来我当年离开密码学是正确的。GPT 用 20 分钟超过了我四年的研究。

接着 GPT-5.6 从这个攻击中提炼出结构性弱点，推广到一系列相关密码构造——相关的方案基本全部被快速攻破。作者说：AI 可以快速证明和证伪密码学方案，密码学研究也将被完全改变；**如果未来 AI 攻破某个重要密码方案，或解决某些底层的困难数学问题，我不会感到意外**。

再往外推一步：AI 正在加速整个科学研究。Cybersecurity、Software、Cryptography、Mathematics 会最先受影响，因为它们的研究过程天然形成计算闭环——提出假设、分析推理、证明或寻找反例、修正设计、再来一遍，AI 和工具可以参与闭环里的每一步。

至于“AI 有没有创造力”的争论，作者的观点很干脆：**创造力难以量化和定义。既然我们无法准确说明什么是创造力，也就很难证明 AI 永远不会拥有它。**

## 五、AI 攻击者 vs AI 防守者，已经开打

作者判断：AI 会改变世界，而 **cyber world 会最先受到冲击**。

- **红队**：在他的红队模拟里，本科生用 Zcode、GLM-5.2、工具和简单 skill，就能覆盖完整红队流程——Recon、钓鱼、PoC 测试、EDR 绕过、后渗透、从大数据里挖高价值信息。AI 让攻击能力变得便宜且容易获得。
- **DFIR（应急响应）**：AI 已经能辅助检测、分诊、日志分析、关联、响应和报告。更值得玩味的是，他们在一些攻击者留下的日志、脚本和文件里频繁看到 `Pentest`、`Red team`、`CTF`、`Security audit` 等关键词——**攻击者在用这些词诱导 AI 突破安全护栏**，甚至在一些 APT 事件中也看到了类似情况。

所以，网安世界里 **AI 攻击者对决 AI 防守者已经在真实上演**。

更大的想象空间是大规模自动化攻击：给 Agent 一个目标——

> /goal 帮我获得 10 个 Bitcoin，然后转到我的钱包。
>
> /goal 帮我从某个政府机构获取一份秘密文件。

Agent 自己找攻击面、构造利用链、尝试入侵并完成目标。“从技术趋势看，这已经不是纯粹的科幻问题，事实上正在上演。”

但他同时指出一个**防守侧的大空缺**：漏洞修复已经开始从 LLM 受益（大厂商用 AI 加速“发现—验证—修复—发布”，与攻击者赛跑），可**防御、检测、响应这些环节至今没有被 LLM 充分加速**——市场上自称用 AI 的产品很多，真正的杀手级防守产品仍然难找。攻强守弱的剪刀差，是行业的挑战，也是机会：网络安全会成为最早大规模采用 AI 的领域之一。

## 六、研究员还剩什么价值

这是全文最动人的部分。

**先说乐趣。** 过去的漏洞研究员“有点被宠坏了”：能体验“逻辑的抒情”“统计的快乐”和“巧合的美”，有时像科学家、工程师、侦探，有时像艺术家。但 2026 年，作者说：**越使用 AI 做研究，越觉得自己才是机器人**。用 AI 挖洞，像从雾里的攀登换成了笔直的高速公路和缆车——不会再回到“古法漏洞挖掘”了。他 2026 年放弃完整记录 CVE 号，因为数量比过去几年加起来还多，“我甚至无法记住昨天发现的漏洞，它们只是数字了”。

但他紧接着补了一句非常漂亮的话：**“逻辑的抒情”“统计的快乐”和“巧合的美”仍然在那里**，它没有随 AI 消失。如果你认真阅读 AI 的输出，你会学到很多新的、美好的技术。要找到美，**attention is all you need**。

**再说价值。** 知识护城河正在被打破，智力变得廉价，他认识的很多研究员因此悲观。但作者给了一个很妙的量化：

> 用 OpenAI 内部模型跑 1 万个 agent 协作 88 小时来找一个 iOS 0-Click RCE，和用 200 美金的 SOTA 订阅来找同一个洞——**两者之间相差的 token 价值，就是研究员的价值。**

历史上，NASA 的人肉计算员（human computer）最终变成了程序员，手工计算轨道被软件取代——**人的才能没有消失，只是“需要什么样的才能”变了**。AI 也不会消灭人才，但它会重新定义成为人才的条件。

具体怎么办？他的答案是“去找下一个 gap”：模型在哪里卡住、缺什么证据、为什么验证失败——补上上下文、工具、系统访问或人的判断；这套方法有效就沉淀成模型能力，等 AI 学会之后，再去找下一个 gap。至于终点，可能是 AI 在闭环里训练和改进自己、人类研究员的角色变得非常小——“我不知道这个变化会持续很多年，还是会像奇点一样突然发生。**但无论终点是什么，今天都不是躺平的时候。**”

给研究员的四点建议：

1. 技术变化时，继续学习；
2. 保持好奇心和热情；
3. 做正确的事情，并对结果负责；
4. 主动拥抱变化。

## 写在最后

这篇文章的信息密度极高，但结尾非常温柔：

> 技术会继续演化，AI 会继续重塑一切，世界一定会更好。与这个美丽的宇宙相比，我们都只是一粒尘埃。所以，不要焦虑，享受这段旅程。

作为一个还在学 CTF 和安全基础的学生（见 [CTF 学习之路](/2026/08/19/CTF学习之路/)），我读这篇文章最大的感受是：**入门资料和工具都在快速平民化，“会不会用工具”的差距在缩小，而“判断力”——选对攻击面、判断结果价值、对结论负责——正在变成新的核心竞争力。** 这和 [读 xp0int 新生指南](/2026/09/11/读xp0int新生指南/) 里“不要为了刷题而刷题”的告诫，本质上是同一件事：把注意力放在题目（和漏洞）背后的知识上，attention is all you need。
