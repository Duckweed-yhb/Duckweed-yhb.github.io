# 编程面试大学：读 coding-interview-university

## 前言

几年前，一位名叫 John Washam 的 Web 开发者给自己定了个目标：通过 Google 的软件工程师面试。为此他辞职在家，每天自学 8~12 小时，整整持续了 8 个月，并把要学的每一个主题整理成 GitHub 上的任务清单，学完一项就打一个勾。

结局有点出人意料：清单学完，[他被 Amazon 招致麾下](https://startupnextdoor.com/ive-been-acquired-by-amazon/?src=ciu)，成了一名软件开发工程师；而那份原本"简单的学习主题清单"，膨胀成了 GitHub 上 36 万+ Star 的传奇仓库——[coding-interview-university](https://github.com/jwasham/coding-interview-university)（编程面试大学）。

> 在这份清单内的主题会让你拥有足够的知识去面对几乎每家软件公司的技术面试，包括科技巨头：Amazon、Facebook、Google，以及 Microsoft。—— 作者原话

仓库有[完整的中文翻译版](https://github.com/jwasham/coding-interview-university/blob/main/translations/README-cn.md)，这篇就按中文版把它拆开讲清楚：先看它的方法论（这是最值钱的部分），再看主题全景和资源清单，最后给出我自己的使用建议。

---

## 一、这是什么：一份"以 Offer 为终点"的 CS 速成大纲

先明确三个定位：

1. **它面向软件工程（后端/系统）方向**，不是前端或全栈——那两条路它直接指向了 [roadmap.sh](https://roadmap.sh/)（我之前写过的[《读 roadmap.sh CS 路线图》](https://duckweed-yhb.github.io/2026/09/11/CS路线图解读/)正好是姊妹篇）；
2. **它只需要大学 CS 专业约 75% 的内容**——剩下 25% 对面试没用，作者直接砍掉了；
3. **它是"训练计划"而不是"课程表"**：每个主题 = 看视频 + 用自己的语言实现一遍 + 立刻刷 2~3 道对应的面试题。

入门要求只有三条：一点编程经验（变量、循环、函数）、耐心、时间。

仓库结构分三大块：

| 区块 | 内容 | 性质 |
|------|------|------|
| 学习计划 | Big-O → 数据结构 → 树 → 排序 → 图 → 更多知识 → 最终复习 | 必修 |
| 获得工作机会 | 简历、面试流程、行为面试、反问面试官 | 必修 |
| 额外主题 | 系统设计、附加学习、视频系列、论文 | **全部可选** |

注意它**不包含** JavaScript、HTML/CSS、SQL——不是它们不重要，而是大厂软件工程师面试基本不考。

## 二、方法论：作者踩过的四个坑

这份清单最好的部分，其实是作者用数月时间换来的四条教训。**把这四条读进去，能省你几个月。**

### 1. 用任务清单管理进度

Fork 仓库 → 克隆到本地 → 每学完一个主题就在 Markdown 方框里打 `x`。打勾本身就是反馈，也是坚持的动力（这个用法我在[《从零造轮子》](https://duckweed-yhb.github.io/2026/08/28/从零造轮子/)里也提过，学长式清单的通用玩法）。

### 2. 你不可能把所有东西都记住

作者看了几百小时视频、记了大量笔记，几个月后发现大部分都忘了。他的解法是**抽认卡（Flashcards）**：把知识点做成一问一答的卡片，反复过卡片直到每张都能秒答。

- 工具推荐 [Anki](http://ankisrs.net/)（多平台、云端同步，除 iOS 外免费）；
- **别学他**：作者做了近 3000 张卡，连汇编和机器学习的边角知识都塞进去了——他自己承认这是过头了，"对要求来说是多余的"。

### 3. 边学边刷题（最重要的一条）

> **在学习这些内容的过程中不断做问题，而不是之后。**

每学完一个主题（比如链表），就立刻去面试书或 LeetCode 上做 2~3 道链表题，然后继续学下一个主题，过几天再回头做几道。作者原话：**"你被雇佣的不是因为你的知识，而是因为你知道如何应用这些知识。"**

### 4. 专注

自学数月，最大的敌人是分心。作者的土办法：放纯音乐。

### 附：语言怎么选

作者的双语言策略很值得抄：

| 用途 | 语言 | 理由 |
|------|------|------|
| 学习概念 | **C** | 能摸到指针和内存分配/释放，数据结构不再是被高级语言隐藏的黑盒 |
| 学习概念 | **Python** | 现代灵活，面试时代码量少 |
| 大厂面试 | C++ / Java / Python | 大公司基本只认这三门 |
| （受限可选） | JavaScript / Ruby | 部分公司允许，需提前查清 |

## 三、主线全景：从 Big-O 到最终复习

必修部分按依赖顺序排开，我把它整理成一张总图：

| 模块 | 覆盖内容 | 备注 |
|------|---------|------|
| 算法复杂度 | Big-O / Ω / Θ、摊还分析 | 只看视频记笔记，无需实现 |
| 基础数据结构 | 数组、链表、栈、队列、哈希表 | **每个都要亲手实现** |
| 更多的知识 | 二分查找、按位运算（补码、置位、交换） | 哈希表前的必备弹药 |
| 树 | 树的遍历、BST、堆/优先级队列 | 平衡树只讲概念不抠细节 |
| 排序 | 选择、插入、堆排、快排、归并 | 重点考"稳定性"与复杂度场景 |
| 图 | 4 种表示法、BFS/DFS、Dijkstra、拓扑排序、强连通分量 | 全计划最长的一章 |
| 更多知识 | 递归、**动态规划**、设计模式、组合与概率、NP 完全、缓存（LRU）、进程与线程、测试、字符串搜索、字典树、浮点数、Unicode、字节序、网络 | 面试的"杂项题库" |
| 最终复习 | 一系列 2~5 分钟短视频 | 考前快速过一遍 |

### 它细到什么程度？

拿"动态数组"举例，清单给的实现要求是这样的：

```
size()          —— 数组元素的个数
capacity()      —— 可容纳元素的个数
is_empty()
at(index)       —— 返回对应索引的元素，越界则报错
push(item)
insert(index, item)
prepend(item)   —— 可用 insert(0, item) 实现
pop()
delete(index)
remove(item)    —— 删除所有指定值的元素
find(item)      —— 未找到返回 -1
resize(new_capacity)  —— 满了翻倍，装到 1/4 时减半
```

连"扩容时机选 1/4 而不是 1/2"这种细节都写好了。链表、哈希表、堆、图同样各有一份完整 API 清单——**这就是"实现优先"的具体形态**。

作者的三个配套练习仓库可以直接参考：[practice-c](https://github.com/jwasham/practice-c)、[practice-cpp](https://github.com/jwasham/practice-cpp)、[practice-python](https://github.com/jwasham/practice-python)。

## 四、刷题：不是为了背答案

> **编程问题练习并不是为了记住解决编程问题的答案。**

刷题训练的是六件事：识别问题并选对数据结构、收集需求、**口头表达解题过程**、在白板/纸上写代码、分析时间空间复杂度、测试自己的解。

几个实用细节：

- **白板或纸笔优先，键盘其次**：先手写 + 手动跑样例，再上机验证。作者家没有白板，就买了个大幅画本坐沙发上练——他称之为"沙发白板"，用铅笔和橡皮（钢笔没法擦）；
- **方法论**：推荐 [算法设计画布](http://www.hiredintech.com/algorithm-design/)，教你有条理地沟通解题；
- **速查**：[Big-O 速查表](http://bigocheatsheet.com/)，复杂度一图流。

刷题网站与视频清单：

| 类型 | 资源 |
|------|------|
| 刷题网站 | [LeetCode](https://leetcode.com/)（作者最爱，冲刺期订阅值得）、[HackerRank](https://www.hackerrank.com/)、[TopCoder](https://www.topcoder.com/)、[Codeforces](https://codeforces.com/)、[Codility](https://codility.com/programmers/)、[GeeksforGeeks](https://practice.geeksforgeeks.org/explore/?page=1)、[AlgoExpert](https://www.algoexpert.io/product)、[Project Euler](https://projecteuler.net/)（偏数学） |
| 解题视频 | IDeserve（88 个）、Tushar Roy、Nick White 的 LeetCode 解答（187 个，短平快）、FisherCoder |
| 模拟面试 | [interviewing.io](https://interviewing.io)（与 FAANG 资深工程师匿名对练）、[Pramp](https://www.pramp.com/)（同行互面）、Meetapro、Hello Interview |

## 五、书单：一本打底，两本冲面

**数据结构与算法教材（选一门语言的版本）**：

- C：Sedgewick《算法：C 语言实现（第 1~5 部分）》
- Python：Goodrich 等《Python 数据结构与算法》
- Java：Sedgewick《算法（第 4 版）》 + 配套免费 Coursera 课程（作者亲自授课）
- C++：Goodrich 或 Sedgewick 版本任选

**面试准备书（按顺序）**：

1. [Programming Interviews Exposed](https://www.amazon.com/Programming-Interviews-Exposed-Through-Interview/dp/111941847X/) —— 热身用，难度略低于真实面试；
2. [Cracking the Coding Interview, 6th Ed](http://www.amazon.com/Cracking-Coding-Interview-6th-Programming/dp/0984782850/)（CTCI，业界人称"绿宝书"）—— 大概率这一本就够了；
3. 时间充裕再加：Elements of Programming Interviews（C++/Java/Python 三个版本任选）。

可选加餐书单里值得点名的是《算法设计手册》（Skiena）——它的后半本"算法目录"是按问题找算法的兵器谱；《算法导论》（CLRS）则被作者特别提醒：**读它的价值有限，它不教你写好代码**。

## 六、从简历到 Offer

这部分常被忽略，但它是整份计划的"出口"：

- **简历**：CTCI 作者 Gayle McDowell 的[简历指南](https://www.careercup.com/resume) + [Tech Interview Handbook 的逐步指南](https://www.techinterviewhandbook.org/resume/guide)；
- **面试流程**：Gayle 本人的 [CTCI 演讲视频](https://www.youtube.com/watch?v=rEJzOhC5ZtQ)值得一看；
- **行为面试**：对着 20 个问题（"你解决过的最难问题？""见过最好/最坏的设计？""最硬的 Bug？"）每题准备 2~3 种回答，**准备故事而不是数据**——"人人都喜欢听故事"；
- **反问面试官**：给了 10 个示例，从"团队多大规模"到"工作生活怎么平衡"——反问环节同样是加分题；
- **拿到 Offer 之后**：恭喜，然后继续学习。"活到老，学到老。"

## 七、可选进阶：半个"高阶 CS"

主线之下还有整整半仓库的可选内容，量非常大，按需取用：

**系统设计**（4 年以上工作经验的面试几乎必考）：

- 入口是 [The System Design Primer](https://github.com/donnemartin/system-design-primer)（这本身也是个几十万 Star 的名仓库）；
- 核心词：CAP 定理、Paxos/Raft 共识、一致性哈希、分片、NoSQL 模式；
- 配着一堆真实工程案例（YouTube、Netflix、Instagram、PayPal、Salesforce 的扩展性文章），还有 5 道纸面练习题（设计短链系统、键值数据库、推荐系统……）。

**附加学习**（按兴趣挑）：

- 平衡树全家桶：AVL、伸展树、红黑树、2-3 树、2-3-4 树、B 树——作者选伸展树实现，并解释了每种的实战用途（Linux 完全公平调度器用红黑树、Java 8 的 HashMap 桶内链表改红黑树等）；
- 概率型数据结构：布隆过滤器、HyperLogLog（1.5KB 内存数十亿不同对象）、局部敏感哈希；
- 其它硬货：A* 搜索、快速傅里叶变换、跳表、网络流、并查集、树堆、线性规划、凸包、离散数学；
- 系统周边：编译器、Emacs/vim、Unix 命令行、信息论、密码学、压缩、垃圾回收、并行编程、消息队列/序列化（Kafka、RabbitMQ、gRPC、Thrift……）。

**视频系列与论文**：MIT 6.006/6.046/6.851、UC Berkeley 61B/61C 等公开课全家桶；经典论文从 Hoare 的《通信顺序处理》到 Google 三大件（[GFS](http://static.googleusercontent.com/media/research.google.com/en//archive/gfs-sosp2003.pdf)、[MapReduce](http://static.googleusercontent.com/media/research.google.com/en//archive/mapreduce-osdi04.pdf)、[Bigtable](https://static.googleusercontent.com/media/research.google.com/en//archive/bigtable-osdi06.pdf)）和 Amazon 的 [Dynamo](http://s3.amazonaws.com/AllThingsDistributed/sosp/amazon-dynamo-sosp2007.pdf)。

> 说句题外话：可选区里也躺着 NAND to Tetris——我在[《从零造轮子》](https://duckweed-yhb.github.io/2026/08/28/从零造轮子/)里称它为"费曼式学习的终极实践"，看来所有通往深度理解的路最后都汇合了。

## 八、怎么用它：结合自身路线

### 它和我之前写的几篇正好互补

| 这份计划给什么 | 我之前的文章给什么 |
|--------------|------------------|
| **面试导向的训练清单**：实现 + 刷题 + 复习的闭环 | [roadmap.sh CS 路线图](https://duckweed-yhb.github.io/2026/09/11/CS路线图解读/)：科班知识的全景地图 |
| **把数据结构练到白板级** | [算法竞赛入门](https://duckweed-yhb.github.io/2026/09/06/算法竞赛入门/)：把算法练到竞赛级 |
| 必修主线学完的数据结构，正好拿去造轮子 | [build-your-own-x](https://duckweed-yhb.github.io/2026/08/28/从零造轮子/)：造数据库、Redis、Git 的实践清单 |

一个合理的组合：**CIU 当训练大纲，roadmap 当查漏清单，build-your-own-x 当实战出口**。比如学完哈希表 → 去刷 3 道 hash 题 → 再去照 [write-a-hash-table](https://github.com/jamesroutley/write-a-hash-table) 造一个自己的哈希表。

### 给不同人群的建议

- **冲大厂/转行的同学**：直接照作者的方法执行——Fork、打勾、抽认卡、边学边刷题，别跳过方法论那一节；
- **在校生**：不必 8 个月脱产。把必修主线当"数据结构与算法的复习总纲"（比考研 408 的数据结构部分更工程视角），系统设计和论文部分留到找实习前再看；
- **只想了解全景的**：读完第二节方法论 + 第三节总图就够本了，四条教训本身比几百个链接值钱。

### 一点提醒

- 仓库采用 **CC-BY-SA-4.0** 协议，整理引用时注明来源即可；
- 视频（Coursera 等）链接偶有失效，以[仓库最新版](https://github.com/jwasham/coding-interview-university)为准；
- 作者反复强调：**你不需要像我一样学这么多**——他在不必要的事情上浪费了大量时间，这份清单正是替你省掉那些时间的。

## 写在最后

这份清单最动人的地方，不是 36 万 Star，而是它背后那个笨办法：**把一个模糊的梦想（"进 Google"），拆成一张可以逐项打勾的清单，然后用 8 个月把勾一个个填满。**

白板上那些行云流水的代码，没有魔法，只有肌肉记忆。所谓"面试运气"，不过是准备到了别人没准备的地方。

> What I cannot create, I do not understand.

这句话我在《从零造轮子》的开头引过——在这里它换了个说法：**你无法在白板上复现的知识，就不是你真正掌握的知识。**

去把仓库 Fork 了吧，从 Big-O 的第一个勾开始。
