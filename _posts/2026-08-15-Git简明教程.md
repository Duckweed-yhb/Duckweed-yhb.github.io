# Git 入门教程

## 一、Git 简介

**Git** 是目前最常用的分布式版本控制系统：记录每次文件改动、可随时回退到历史版本，每个人的电脑上都是完整版本库，分支管理轻量高效。

## 二、安装 Git

| 平台 | 下载地址 |
|---|---|
| Windows | [Git for Windows](http://msysgit.github.io/) |
| macOS | [Git for Mac](http://git-scm.com/download/mac) |
| Linux | [Git for Linux](http://git-scm.com/download/linux) |

安装完成后，在终端（或 Git Bash）中输入以下命令验证：

```bash
git --version
```

## 三、初次配置

安装完 Git 之后，首先要配置你的用户名和邮箱，因为每次提交都会记录这些信息：

```bash
git config --global user.name "你的名字"
git config --global user.email "your_email@example.com"
```

> 加上 `--global` 表示全局生效，对本机所有 Git 仓库都适用。

## 四、核心概念：Git 工作流

你的本地仓库由 Git 维护的 **三棵"树"** 组成：

```
工作目录 (Working Directory)       ← 你正在编辑的实际文件
        │  git add
        ▼
暂存区 (Index / Stage)             ← 临时存放你的改动
        │  git commit
        ▼
HEAD                               ← 指向你最后一次提交
        │  git push
        ▼
远程仓库 (Remote Repository)
```

简单来说，一次完整的提交流程是：

1. 在工作目录中修改文件
2. 用 `git add` 将改动添加到暂存区
3. 用 `git commit` 将暂存区内容提交到本地仓库（HEAD）
4. 用 `git push` 将本地提交推送到远程仓库

## 五、创建与克隆仓库

### 5.1 初始化新仓库

将当前目录初始化为 Git 仓库：

```bash
git init
```

指定目录创建：

```bash
git init newrepo
```

### 5.2 克隆已有仓库

克隆本地仓库：

```bash
git clone /path/to/repository
```

克隆远程服务器上的仓库：

```bash
git clone username@host:/path/to/repository
```

克隆 GitHub 上的仓库：

```bash
git clone https://github.com/username/repo.git
# 或使用 SSH
git clone git@github.com:username/repo.git
```

## 六、添加与提交

### 6.1 添加文件到暂存区

```bash
# 添加指定文件
git add filename

# 添加所有文件
git add *

# 添加当前目录所有文件
git add .
```

### 6.2 提交到本地仓库

```bash
git commit -m "代码提交信息"
```

> 提交信息请尽量写清楚改了什么，方便日后回顾。如果不加 `-m`，会弹出编辑器让你输入提交信息。

### 6.3 一键提交已跟踪文件的改动

当你修改了多个已被 Git 管理的文件，不想逐个 `git add`，可以使用 `-a` 参数：

```bash
git commit -a -m "Changed some files"
```

> ⚠️ 注意：`-a` 只会自动暂存**已被 Git 跟踪**且**已修改/删除**的文件，**新文件**不会被自动添加。

## 七、推送到远程仓库

### 7.1 推送改动

将本地提交推送到远程仓库：

```bash
git push origin master
```

> `master` 可以换成任意分支名。

### 7.2 关联远程仓库

如果你还没有克隆现有仓库，需要先将本地仓库与远程仓库关联：

```bash
git remote add origin <server>
```

示例：

```bash
git remote add origin git@github.com:yourName/yourRepo.git
```

## 八、分支操作

分支用于将特性开发隔离开来。创建仓库时，`master` 是默认的主分支。你可以在其他分支上开发新功能，完成后再合并到主分支。

### 8.1 创建并切换分支

```bash
# 创建新分支
git branch test

# 切换到新分支
git checkout test

# 创建并切换（一步到位）
git checkout -b feature_x
```

### 8.2 查看分支

```bash
# 查看本地分支
git branch

# 查看所有分支（含远程）
git branch -a
```

### 8.3 切换分支

```bash
git checkout master
```

### 8.4 删除分支

```bash
git branch -d feature_x
```

### 8.5 推送分支到远程

```bash
git push origin <branch>
```

> 除非你将分支推送到远端仓库，不然该分支只在本地可见。

## 九、更新与合并

### 9.1 拉取远程更新

```bash
git pull
```

`git pull` 相当于 `git fetch` + `git merge`，即先获取远程改动，再自动合并到当前分支。

从指定 URL 更新：

```bash
git pull http://git.example.com/project.git
```

### 9.2 合并分支

将其他分支合并到当前分支：

```bash
git merge <branch>
```

示例：将 `feature_x` 合并到 `master`

```bash
git checkout master
git merge feature_x
```

### 9.3 预览差异

在合并之前，可以先查看两个分支之间的差异：

```bash
git diff <source_branch> <target_branch>
```

### 9.4 解决冲突

当 Git 无法自动合并时，会产生**冲突（conflicts）**。此时你需要：

1. 手动编辑冲突文件，保留需要的代码
2. 将修改后的文件标记为已解决：

```bash
git add <filename>
```

3. 完成合并提交：

```bash
git commit -m "解决冲突"
```

## 十、标签管理

标签通常用于标记发布版本（如 v1.0.0）。

### 10.1 查看提交 ID

```bash
git log
```

输出示例：

```
commit 1b2e1d63ffc8e9f4a3b7d6...
Author: yourname <your@email.com>
Date:   Mon Jan 1 12:00:00 2026 +0800

    某个提交信息
```

### 10.2 创建标签

```bash
git tag 1.0.0 1b2e1d63ff
```

`1b2e1d63ff` 是提交 ID 的前 10 位（取前几位即可，只要唯一）。

### 10.3 推送标签到远程

```bash
git push origin --tags
```

## 十一、撤销与回退

### 11.1 撤销工作区的修改

```bash
git checkout -- <filename>
```

> 此命令会用 HEAD 中的最新内容替换工作目录中的文件。**已添加到暂存区的改动不受影响**。

### 11.2 丢弃所有本地改动与提交

```bash
git fetch origin
git reset --hard origin/master
```

> ⚠️ 此操作会丢弃本地所有未推送的改动，请谨慎使用。

### 11.3 取消暂存

```bash
git reset HEAD <filename>
```

## 十二、删除文件

### 12.1 从仓库中删除文件

```bash
git rm file
```

此命令会同时从工作目录和暂存区删除文件。之后需要提交：

```bash
git commit -m "删除 file"
```

### 12.2 仅从暂存区删除（保留工作目录文件）

```bash
git rm --cached file
```

## 十三、连接 GitHub

[GitHub](https://github.com/) 是基于 Git 的代码托管平台。

### 13.1 注册 GitHub 账号

访问 [https://github.com/](https://github.com/) 注册账号，免费用户可以创建**公共仓库**，付费用户可以创建私有仓库。

### 13.2 配置 SSH Key

**第一步**：生成本机 SSH Key

```bash
ssh-keygen -t rsa -C "your_email@youremail.com"
```

> 将邮箱换成你在 GitHub 上注册的邮箱，之后一路回车即可。

**第二步**：复制公钥内容

生成的密钥位于 `~/.ssh/` 目录下。打开 `id_rsa.pub`，复制里面的全部内容。

**第三步**：添加到 GitHub

进入 GitHub → Settings → SSH and GPG keys → New SSH key，粘贴公钥内容，保存。

**第四步**：验证连接

```bash
ssh -T git@github.com
```

看到 `You've successfully authenticated` 即表示连接成功。

### 13.3 将本地仓库推送到 GitHub

```bash
# 关联远程仓库
git remote add origin git@github.com:你的用户名/你的仓库名.git

# 推送代码
git push -u origin master
```

> `-u` 参数会将本地 master 分支与远程 master 分支关联，之后只需 `git push` 即可。

### 13.4 在 GitHub 上创建仓库后直接克隆

```bash
git clone git@github.com:你的用户名/你的仓库名.git
```

## 十四、实用技巧

| 命令 | 说明 |
|---|---|
| `gitk` | 打开内建的图形化 Git 界面 |
| `git config color.ui true` | 彩色 git 输出，更易阅读 |
| `git config format.pretty oneline` | 历史记录每条提交只显示一行 |
| `git add -i` | 交互式添加文件到暂存区 |
| `git log --oneline --graph` | 图形化查看提交历史 |
| `git stash` | 暂存当前工作进度，稍后恢复 |
| `git stash pop` | 恢复最近一次 stash 的内容 |
| `git status` | 查看当前工作区状态 |

## 十五、规范 Commit 提交信息

### 15.1 规范来源
经典 7 条 Commit 提交准则出自：
https://chris.beams.io/git-commit

### 15.2 七大核心规则
1. 标题行控制在 **50 字符以内**
2. 标题行使用祈使句式（动词原形开头）
3. 标题首字母大写
4. 标题末尾不要加句号
5. 标题与正文之间空一行分隔
6. 正文每行控制在 **72 字符自动换行**
7. 正文用来解释「做了什么、为什么这么改」，而非描述代码如何实现

### 15.3 常用类型前缀（团队通用约定）
```
feat: 新增功能
fix: 修复 bug
docs: 文档修改
style: 格式、空格、标点调整，不影响代码逻辑
refactor: 代码重构，无功能新增无 bug 修复
perf: 性能优化
test: 添加/修改测试用例
chore: 构建、工具、依赖、配置文件更新
```

### 15.4 标准示例
```
feat: 新增用户登录接口

1. 实现账号密码校验逻辑
2. 生成 JWT 令牌返回给前端
3. 添加接口异常捕获处理
```

### 15.5 交互式修改历史提交备注
```bash
# 交互式改写最近 3 次 commit 信息
git rebase -i HEAD~3
```
