# 命令行的艺术

## 前言

熟练使用命令行，是一种常常被忽视、甚至被认为难以掌握的技能。但实际上，它会实实在在提高你作为工程师的灵活性与生产力。

这篇整理自 [the-art-of-command-line](https://github.com/jlevy/the-art-of-command-line)（多作者共同维护的开源项目，采用 CC BY-SA 4.0 协议，在此致谢），我从数百条技巧里挑出最常用、最值得掌握的，按「基础 → 日常 → 数据处理 → 调试 → 脚本」的顺序组织成一份能反复翻阅的清单。如果你用得顺手，强烈建议直接去读[中文原版](https://github.com/jlevy/the-art-of-command-line/blob/master/README-zh.md)。

## 一、基础（地基要打牢）

以下属于命令行世界的「基本功」，值得逐条过一遍：

| 主题 | 要点 |
|------|------|
| Bash 手册 | 输入 `man bash` 至少浏览一遍，理解起来很简单 |
| 文本编辑器 | 至少精通一个，终端里 Vim 通常是最好的选择 |
| 查文档 | `man` 读文档、`apropos` 查文档、`help` 查内置命令、`type` 判断命令类型 |
| 重定向 | `>` 覆盖、`>>` 追加、`\|` 管道；分清 stdout 和 stderr |
| 通配符 | `*`、`?`、`[...]`，以及单引号 `'` 与双引号 `"` 的区别 |
| 任务管理 | `&`、`ctrl-z`、`ctrl-c`、`jobs`、`fg`、`bg`、`kill` |
| 远程登录 | `ssh`，最好再掌握 `ssh-agent` 无密码登录 |
| 文件管理 | `ls -l`、`less`、`head`、`tail -f`、`ln -s`、`chown`、`chmod`、`du`、`df` |
| 网络管理 | `ip`/`ifconfig`、`dig` |
| 正则 | 学会 `grep`/`egrep`，重点掌握 `-i`、`-o`、`-v`、`-A`、`-B`、`-C` |
| 包管理 | `apt-get`、`yum`、`dnf` 或 `pacman`，再配一个 `pip` |

> 顺带一提：本文主要针对 Linux 交互式 Bash 环境。Windows 用户可以借助 WSL、Git Bash 或 Cygwin 获得几乎一致的体验。

## 二、日常使用（每天都要用）

### 编辑行内命令的快捷键

在 Bash 里，编辑一条命令其实有一套完整的快捷键，记熟几个高频的就够：

| 快捷键 | 作用 |
|--------|------|
| **Tab** | 自动补全 |
| **ctrl-r** | 反向搜索历史命令 |
| **ctrl-a / ctrl-e** | 光标移到行首 / 行尾 |
| **ctrl-u / ctrl-k** | 删除光标前 / 光标后所有内容 |
| **ctrl-w** | 删除上一个单词 |
| **alt-b / alt-f** | 按单词移动光标 |
| **alt-.** | 循环取上一个命令的参数 |
| **ctrl-l** | 清屏 |

> 详细列表可以 `man readline` 查看。喜欢 vi 风格的话，`set -o vi` 一键切换，`set -o emacs` 切回来。

### 历史命令的几个小技巧

- `history` 查看历史，`!n` 执行第 n 条，`!!` 执行上一条，`!$` 取上一条命令的最后一个参数。
- 输入到一半改了主意？按 **alt-#**（或 `ctrl-a`、`#`、回车）把它变成注释存进历史，之后想用还能翻出来。

### 进程管理

```bash
pstree -p              # 以树状展示进程
pgrep -f name          # 按名字找进程
pkill -f name          # 按名字杀进程
kill -STOP [pid]       # 暂停进程（man 7 signal 看全部信号）
nohup cmd &            # 后台运行，退出终端也不中断
```

### 端口与系统状态

```bash
ss -plat              # 谁在监听端口
lsof -iTCP -sTCP:LISTEN -P -n   # 同上（macOS 也能用）
uptime / w            # 系统运行了多久
```

### 别名与配置

- `alias ll='ls -latr'` 创建别名，把常用别名存进 `~/.bashrc`，会话通用。
- 环境变量放 `~/.bash_profile`；用 Git 在多台机器间同步配置文件。
- 变量和文件名含空格时**务必加引号**：`"$FOO"`；find 管道建议 `-print0` + `xargs -0`。

## 三、脚本写作（严谨是美德）

### 脚本开头三件套

写脚本时，开头加上这行几乎能防住一半的坑：

```bash
set -euo pipefail
```

- `set -e`：出错立即退出，而不是带着错误继续跑
- `set -u`：使用未赋值的变量直接报错
- `set -o pipefail`：管道中任一命令失败都算失败

调试时用 `set -x` 打印每条执行的命令。想捕获错误可以加 `trap`：

```bash
trap "echo 'error: Script failed'" ERR
```

### 变量的进阶用法

```bash
${name:?error}          # 变量未定义就报错退出
input_file=${1:?usage: $0 input_file}   # 必填参数
output_file=${2:-logfile}               # 可选参数带默认值
i=$(( (i + 1) % 5 ))    # 数学运算
{1..10}                 # 序列
${var%.pdf}.txt         # 去掉后缀再拼新后缀（假设 var=foo.pdf → foo.txt）
```

### 括号扩展与子 shell

```bash
mv foo.{txt,pdf} some-dir        # 一次移动两个文件
cp somefile{,.bak}               # 等价于 cp somefile somefile.bak
(cd /some/other/dir && cmd)      # 子 shell 里临时切换目录，不影响当前目录
diff /etc/hosts <(ssh host cat /etc/hosts)   # 进程替换：把命令输出当文件
```

### 重定向与 here document

```bash
cmd >logfile 2>&1      # stdout 和 stderr 一起进文件
cat <<EOF              # here document，多行输入
...
EOF
```

## 四、文件与数据处理（命令行的主场）

### 查找与检索

```bash
find . -iname '*something*'   # 当前目录按文件名查找（忽略大小写）
locate something              # 全盘查找（注意 updatedb 索引可能滞后）
grep -r pattern .             # 递归检索（进阶可用 ag / ripgrep）
```

### 文本处理三兄弟

- **`sort` / `uniq`**：排序与去重。`sort -n` 按数字排、`-h` 按人类可读大小排；`uniq -d` 只显重复行、`-u` 只显唯一行。配合 `-t` 和 `-k` 可以按指定列排序。
- **`cut` / `paste` / `join`**：很多人会用 `cut`，却忘了 `join`。它们是文本表格处理的主力。
- **`awk` / `sed`**：简单数据处理的两大神器，值得专门学一遍。

### 编码与格式转换

```bash
iconv -f gbk -t utf-8 old.txt > new.txt   # 编码转换
lynx -dump -stdin                          # HTML → 纯文本
pandoc in.md -o out.pdf                    # 各种文档格式互转
jq '.key' data.json                        # JSON 处理
```

### 其他高频操作

```bash
ls -al | tee file.txt        # 输出同时写入文件（tee）
wc -l file                  # 数行数（-m 字符、-w 单词、-c 字节）
shuf file                   # 打乱文件行序 / 随机取行
rsync -r --delete empty/ some-dir   # 快速删除大量文件
diff -r tree1 tree2 | diffstat       # 目录对比 + 变更统计
strings binary | grep secret        # 从二进制里挖字符串
```

> 注意：`LANG` 语言环境会影响 `sort` 的顺序和性能。做集合运算时可以放心 `export LC_ALL=C` 按字节序排。

## 五、系统调试（排查问题的工具箱）

| 场景 | 命令 |
|------|------|
| 网络调试 | `curl -I`、`wget`、`mtr`、`traceroute` |
| CPU / 内存 | `top`/`htop`、`free`、`vmstat`、`iostat` |
| 磁盘占用 | `ncdu`（交互式，比 `du` 直观） |
| 端口监听 | `ss -plat`、`lsof -iTCP -sTCP:LISTEN` |
| 跟踪路由 | `mtr` |
| 系统调用跟踪 | `strace -p [pid]`（程序挂起、崩溃时的大杀器） |
| 崩溃堆栈 | `gdb` 附加到运行中的进程 |
| 系统信息 | `uname -a`、`lsb_release -a`、`dmesg` |
| 历史性能 | `sar`（CPU、内存、网络的过去数据） |

其中 `strace` 值得多说一句：程序跑挂了你却不知道为什么，`strace -p` 附上去看它到底在做什么系统调用，往往一眼就能定位问题。

## 六、单行脚本（一行顶十行）

```bash
# 集合运算：a 并 b / a 交 b / a 减 b
sort a b | uniq > c          # 并集
sort a b | uniq -d > c       # 交集
sort a b b | uniq -u > c     # 差集

# 计算第三列之和
awk '{ x += $3 } END { print x }' myfile

# 统计日志里每个 acct_id 的出现次数
egrep -o 'acct_id=[0-9]+' access.log | cut -d= -f2 | sort | uniq -c | sort -rn

# 持续监测目录变化
watch -d -n 2 'ls -rtlh | tail'
```

## 写在最后

原文档结尾有句免责声明，我特别认同：*除去特别小的工作，你编写的代码应当方便他人阅读。能力往往伴随着责任——你有能力在 Bash 里玩奇技淫巧，并不意味着你应该去做*。

命令行的艺术，不是背下多少奇技淫巧，而是**在合适的场景用合适的工具，并把工具用到顺手**。把这份清单当作地图，遇到问题回来翻一翻，日积月累，你也会有自己的「三板斧」。
