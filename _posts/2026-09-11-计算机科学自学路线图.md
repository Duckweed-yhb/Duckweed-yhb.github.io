# 计算机科学自学路线：roadmap.sh CS Roadmap

## 前言

我之前的文章《我的学习路线》和《计算机自学之路》里，都绕不开一个问题：**科班学生四年到底在学什么？自学者要按什么顺序补齐？**

[roadmap.sh](https://roadmap.sh/computer-science) 的 **Computer Science Roadmap** 就是为这个问题准备的。它是 GitHub 上 Star 数排第六的 [developer-roadmap](https://github.com/kamranahmedse/developer-roadmap) 项目（36 万+ Star）中的一张路线图，定位很明确：

> **Computer Science curriculum with free resources for a self-taught developer.**
> （为自学者准备的计算机科学课程大纲，每个知识节点都配了免费学习资源。）

官方的定位是"自学家（self-taught developer）的 CS 教学大纲"。当然同样**适合想系统补课的学生党**——尤其是那些觉得"课上学的和数据结构与算法At什么关系"的同学，顺着这张图走一遍，就知道哪些知识在体系中扮演什么角色。

在这篇导航，我把整张图拆开、展开、翻译成人话，再给出我的使用建议。

---

## 一、整体结构：一条从底层绞尽的主线

整张图没有框在"第 1 学期 / 第 2 学期"这种杯子里，而是以**节点树（层级图）**的方式组织——大部件套小题、每个节点点进去都有资源链接。从上到下大致可以划分成底下这个主线：

![学习顺序建议]

7.  **入门语言 / Pick a Language**
8.  **数据结构与算法 / Data Structures**（本文的主体消耗量最大）

## 二、逐块拆解

### 1. Pick a Language：先选一把趁手的兵器

路线图给出的候选语言非常"一线"：

| 语言 | 一句话点评 |
|------|-----------|
| **Python** | 最快上手、库生态爆炸，自学首选 |
| **C** | 最贴近 OS/内存模型，理解计算机底层的最佳窗口 |
| **C++** | 算法竞赛、图形学、游戏引擎的主流语言 |
| **Go** | 网络服务、云原生方向友好的"工程派" |
| **Java** | 企业级后端的第一大生态 |
| **C#** | 游戏（Unity）、桌面、企业后端 |
| **Rust** | 内存安全的系统级语言，近年最高人气 |

我的看法：**不要纠结"选错"，先把一门语言学"通"**（包括内存模型、标准库、调试与环境管理），换语言就只是换语法的体力活。我在《我的学习路线》里也提到过——用一门语言学透原理，比用五门语言学皮毛值钱。

### 2. Data Structures：数据结构全景

这是整张图最大的一块，覆盖了：

| 代数 | 常见实现 / 变体 |
|------|----------------|
| 线性结构 | 数组、链表、栈、队列 |
| 哈希 | 哈希表 |
| 堆 | 堆（优先级队列的本质） |
| 树 | 二叉树、BST、满二叉树、完全二叉树、平衡/非平衡树 |
| 图 | 有向图、无向图、生成树；邻接表 / 邻接矩阵两种表示 |

**这里有个坑要点名**：很多人学数据结构只学"是什么"，不学"什么时候用"。比如——

- 需要频繁的<�随机访问、尾部操作题请求 ask/首部操作题>时序问题，用数组还是链表？区别在 cache 命中率与指针开销；
- 需要有序 + 频繁查询时，哈希表 O(1) 听起来快，但缓存友好性可能被其它结构打败；
- 优先级队列为什么是堆而不是排序数组？答案在"取最值"与"插入"的摊还开销。

这些"选择背后的权衡"，是科班训练里最值钱的部分，也是《计算机修仙境界》里"筑基期"境界增突破的原料。

### 3. Algorithms：一张无所不包的算法地图

这是全图最"密集"的一块，可以说是**算法入门课程的完整目录**。我把它们按类别整理如下：

**排序（Sorting）：**

| 类型 | 代表算法 |
|------|---------|
| 交换/选择/插入 | 冒泡、选择、插入 |
| 高效 | 快排、归并、堆排序 |
| 非比较 | 计数、基数、桶排序 |

**递归（Recursion）：** 尾递归 / 非尾递归，以及递归到 DP 不是又必须到转换。

**搜索（Searching）：** 线性查找 / 二分查找。

**图论（Graphs）：**

| 类型 | 代表算法 |
|------|---------|
| 遍历 | BFS、DFS |
| 最短路 | Dijkstra、Bellman-Ford、A* |
| 最小生成树 | Prim、Kruskal |
| 网络流 | Ford-Fulkerson |
| 其它 | 拓扑排序、并查集（Union-Find） |

**树（Tree）：** 前序 / 中序 / 后序遍历，以及树上的 BFS、DFS。

**启发式与组合：**

- 贪心：Dijkstra、Huffman 编码、Kruskal、Ford-Fulkerson、Prim
- 回溯：哈密尔顿路径、N 皇后、走迷宫、骑士巡回
- 动态规划：背包问题（0-1 / 无界）

**缓存策略（Caches）：** LRU、LFU、MRU——工程中 90% 的缓存配置题都逃不掉这三种。

**模式匹配（String Search）：**

| 策略 | 算法 |
|------|------|
| 暴力 | Brute-Force（朴素匹配） |
| 哈希 | Rabin-Karp |
| 前缀函数 | KMP（Knuth-Morris-Pratt） |
| 后缀 | Boyer-Moore、后缀数组 |

**复杂度理论：**

- 渐近记号：Big O / Θ / Ω，以及 little-o / little-ω
- 常见量级：常数 O(1)、对数、线性、多项式、指数、弦式
- 复杂度类：P、NP、CoNP、NPHard、NP Complete
  - 经典 NP 完全问题：旅行商（TSP）、背包问题、最长路径问题

一块网络的基本没漏——**学好这一列，考研数据结构 + 算法设计两门课基本就覆盖了**。

### 4. 设计模式与 UML：写"工程"而不是"代码"

- **GoF 23 种设计模式**：创建型 / 结构型 / 行为型。路线图里点名的依赖注入、空对象模式、类型对象模式，都是现代框架里天天用的东西。
- **架构模式（Architectural Patterns）**：分层架构、MVC/MVVM、事件驱动、微内核……
- **UML**: 类图、用例图、活动图、状态机图、时序图——写设计文档/画架构图的基础能力。

在《工具和网站》一文中我提过，代码规范和设计能力是从"教填空代码"到"能造轮子"的分水领。设计模式是那个分水领的第一站。

### 5. 数学基础：别小看这两块

- **基本数学能力（Basic Math Skills）**：概率、组合数学。
- **复杂度类（Complexity Classes）**：P / NP / CoNP / NPHard / NP-Complete，以及属于 NP 的经典问题（TSP、背包、最长路）。

为什么这些放在 CS 路线图里？因为：

1. **复杂度理论**是"判断一个问题的可行性"的能力——知道哪些问题"没有所想的解"，哪些问题"大概率只有很竣的解"；
2. **概率与组合**是 ML / 数据科学 / 分析算法性能（平均态分析）的基石。

空想"学 CS 不用学数学"可以先扫一眼 NP-Complete 那张图再下结论。

### 6. How Computers Work：往下的到底层

这一列回答"程序在机器上到底怎么跑"：

- CPU 如何执行程序（指令周期）
- 寄存器与 RAM 的分工
- 指令与程序的关系
- CPU Cache（L1/L2/L3、局部性原理）
- 计算机如何完成计算（数字电路视角）

我在《计算机自学之路》里说，校生最容易忽略的反而是这一块。因为应用层开发应用层里，似乎营楼里没它也转——但到了排查性能问题、写并发程序、理解编译器和 OS 时，它就是那里最关键的"排便码表"。

### 7. Processes and Threads：并发程序的基本功

- 进程 fork
- 内存管理（虚拟内存、分页）
- Lock / Mutex / Semaphore
- 多核并发（原子性、内存可见性）
- 调度算法
- CPU 中断
- 进程 vs 线程

这一块是**人类与资本的鸿沟**。并发 bug 不会在开发时出现，但上线后会在凌晨三点绑你。消息队列、锁、信号量的语义，在所有操作系统中只有名字不同,概念完全一致。

### 8. Networking / Databases / System Design / Security：四面"应用层大墙"

- **网络**：OSI 七层 vs TCP/IP 四层、DNS、HTTP、TLS/HTTPS、Socket
- **数据库**：
  - 选型：SQL vs NoSQL
  - 设计：规范化 / 反规范化、E-R 模型
  - SQL 四个子语言：DDL / DML / DQL / DCL
  - 事务：锁、ACID、BASE、CAP、PACELC
  - 执行：索引、视图、存储过程
  - 架构：复制（Replication）、分片（Sharding）、聚合（Federation）
- **系统设计**：水平/垂直扩展、负载均衡、集群、缓存、CDN、消息队列、代理、REST / GraphQL / gRPC、云设计模式、长轮询 / 短轮询 / WebSocket / SSE
- **安全**：哈希 vs 加密 vs 编码、公钥密码学、哈希算法、OWASP Top 10

这四块是从"学生"走向"工程师"的桥。**面试里讲"设计一个短链接 / 设计一个排行榜"，考的全是这里的内容。**

### 9. Balanced Search Trees：一块被低估的"必考题"

路线图把平衡搜索树**单独拎出来一列**，可见它的重要性：

AVL 树、红黑树、2-3 树、2-3-4 树、B 树、B+ 树、K 叉树、K-D 树、跳跃表。

为什么单独立一列？因为它们是**索引的实现、数据库的骨架**：MySQL InnoDB 的索引是 B+ 树，Redis 的 zset 底层一路曾用过跳跃表。理解了它们，"为什么数据库要用 B+ 树而不是哈希表 / 红黑树"这类经典面试题就有了底层答案。

## 三、怎么用这张图？

### 建议一：当"总大纲"用，而不是"课程表"

这张图的最大价值是**呈现知识全貌与依赖关系**：你随时能看到"我现在所在的节点、它跟什么东西相连"。但每个节点的资源只是"推荐起点"，别把它当教材一页页刷。

**我的用法**：工作中学到什么、映似映到图上哪个节点，偶尔带着问题某天（比如今晚学完 DNS）画画图，补充战挂在图上没讲透的资料。

### 建议二：和《 учит的学习路线》 / 《build-your-own-x》搭配

我之前的几篇文章和这张图正好互为补充：

| 这张图给什么 | 之前的文章给什么 |
|-------------|----------------|
| **知识地图**：验证还缺什么 | [我的学习路线](https://Duckweed-yhb.github.io/blog/2026/08/10/我的学习路线/)：宏观顺序 |
| **免费资源清单**：每个节点都有推荐链接 | [build-your-own-x](https://Duckweed-yhb.github.io/blog/2026/08/28/build-your-own-x/)：以"造"代"读"的实践清单 |

**合理的组合姿势**：以 roadmap 当验收清单，学完一个块，就去 build-your-own-x 里找一个对应项目做一遍。比如学完平衡树，就去造一个小型 KV 数据库；学完进程线程，就去写一个 mini shell。

### 建议三：AI Tutor 可以当"答疑助教"

roadmap.sh 现在自带 [AI Tutor](https://roadmap.sh/ai)，点任意节点就能问"给我一个例子 / 帮我讲透 / 出几道题"。可以把它当"随问随答的答疑助教"，但依然提醒：**答案要能复述为自己语言才算是学会**。

### 建议四：别当"追打卡清单"

看到 22 个大项 × 几百个子节点，容易产生"全都要会"的焦虑。其实：

- **铺普面临的最低配置**：语言 + 数据结构与算法 + 计算机原理与进程线程，就能写出可能正确的程序；
- **进阶工程力**：网络 + 数据库 + 系统设计 + 安全；
- **润色加项**：设计模式、UML、复杂度理论——它们让你的代码"体面"，但不是第一优先级。

每一步都推着一块"树干"，枝叶可以后补。《计算机修仙境界》里"筑基期"要补的术法，和这张图里中间稳定性极高的几列几乎是对应的。

## 四、写在最后

roadmap.sh 这类项目的价值，不在于"把一条路走完"，而在于**让你知道路的形状**——你知道自己缺什么、缺的东西长什么模样、缺的程度有多深。

垂直的成长路径很多，但"知道自己在哪里"这件事，是一切学习的起点。这张 CS 路线图，就是一面用来照自己的镜子。

去把它挂在自己的书签里吧，和 [build-your-own-x][byox]、[open-cs][opencs] 一样，都是自学路上最好的"藏宝图"。
