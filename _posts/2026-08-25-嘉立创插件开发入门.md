# 嘉立创插件开发入门

## 前言

嘉立创 EDA 是硬件工程师常用的免费 PCB 设计工具。除了自带的原理图、PCB 绘制功能，它还支持通过**扩展（插件）**来扩展能力——批处理、自动化布线辅助、和 AI 工具对接，都能写成一个个插件。

在嘉立创 EDA 专业版的扩展引擎里，每一个扩展都是一个独立的 JavaScript 脚本，跑在各自独立的作用域里。这意味着你只需要会 JavaScript（或 TypeScript），就能给这款 EDA 工具写插件。

这篇笔记整理一条从零到跑通第一个插件的路线，参考资料来自嘉立创官方开发文档。

---

## 一、认识扩展的 UUID

每个扩展都需要一个唯一标识（UUID）。它有两种情况：

1. **已被官方收录**：从扩展商店引用，或已申请并填写了 `extension.json` 里的 `uuid` 字段——这时 UUID 是自动生成的 32 位字符串，可以在扩展商店页面找到它。

2. **未收录、未填写**：UUID 退化为你在 `extension.json` 里定义的 `name` 字段。**谨慎**用它来做扩展之间的依赖引用，因为它随时可变，还可能重名。

如果你用官方推荐的 `pro-api-sdk` 开发，首次执行 `npm run build` 时会自动帮你生成新 UUID，省心。

---

## 二、开发环境准备

官方推荐使用 `pro-api-sdk`，本文也基于它讲解。需要依次装好以下四样：

| 工具 | 用途 | 要求 |
|------|------|------|
| Visual Studio Code | 推荐的 IDE | 下载 Windows System Installer x64 |
| Git | 拉取 SDK | 官网下载即可 |
| Node.js | 本地编译 TypeScript | 版本 **不低于 20.5.0** |
| pro-api-sdk | 官方开发 SDK | 见下文获取 |

> 提示：在控制台输入 `node -v` 可查看 Node.js 版本，低于 `20.5.0` 请先升级。

---

## 三、获取 SDK 并初始化

先在你的磁盘里建一个用于保存开发资料的文件夹，比如 `D:\jlceda-extension`。

> **注意**：路径里尽量不要有 `空格` 或非 ASCII 字符，以免后续操作出岔子。

然后打开 PowerShell，进入该目录：

```powershell
cd "D:\jlceda-extension"
```

有两种方式拉取 SDK，任选其一：

**方式一：npx 初始化**

```powershell
npx github:easyeda/pro-api-sdk my-extension
```

**方式二：git 克隆**（国内网络建议用 Gitee）

```powershell
git clone --depth=1 https://gitee.com/jlceda/pro-api-sdk.git my-extension
```

国内网络用 Gitee 会快不少。

接着用 VS Code 打开项目文件夹，装好三个推荐扩展（`Code Spell Checker`、`ESLint`、`EditorConfig for VS Code`）。它们 SDK 已预配好，不用额外折腾。

最后初始化依赖：

```powershell
npm install
```

> 中国大陆网络访问 NPM 慢时，可在 `.npmrc` 里取消注释 `registry=https://registry.npmmirror.com`，走国内镜像。
>
> 如果 PowerShell 报 `禁止运行脚本` 的错误，在**管理员权限**下执行 `Set-ExecutionPolicy RemoteSigned` 即可。

---

## 四、项目文件结构

SDK 里已经预配好开发所需的一切，核心文件如下：

```
├── build/           # 扩展包编译目录（dist/ 里是最终产物）
├── config/          # ESBuild 配置
├── images/          # 扩展预览图（banner.png / logo.png）
├── locales/         # 多语言（en.json / zh-Hans.json）
├── src/             # 扩展主要源代码目录（index.ts 是入口）
├── extension.json   # 嘉立创 EDA 扩展配置（关键文件）
├── package.json     # NPM 软件包配置
└── tsconfig.json    # TypeScript 编译配置
```

---

## 五、扩展配置 extension.json

`extension.json` 会被 EDA 完整读取，体现在扩展的展示与运行中。默认内容很长，入门阶段只需改几个关键字段：

| 属性 | 类型 | 示例 | 说明 |
|------|------|------|------|
| `name` | string | `run-api-gateway` | 扩展名称，仅小写字母、数字、中划线，长度 5–30 |
| `displayName` | string | `Run API Gateway` | 展示名称，**可以是中文** |
| `description` | string | `为 AI 编程工具提供 WebSocket 网关桥接服务` | 描述 |
| `publisher` | string | `JLCEDA` | 开发者信息 |
| `license` | string | `Apache-2.0` | 开源协议，可到 [Choose a License](https://choosealicense.com/) 挑选 |
| `version` | string | `1.0.0` | 语义化版本号 `major.minor.patch` |

---

## 六、编写第一个扩展

入口代码文件是 `/src/index.ts`。官方默认支持 TypeScript 开发，配合 `@jlceda/pro-api-types` 类型定义，能获得完善的类型推断和语法提示。

入门阶段，你可以先跑通"打开一个简单的对话框 / 注册一个菜单项"这类最小例子，再逐步调用扩展 API 实现真正的功能。具体 API 用法会在下一篇「调用扩展 API」里展开。

> 如果你更想用原生 JavaScript，把 `/src/index.ts` 改名为 `/src/index.js`，并删掉内部不符合 JS 语法的内容即可。

---

## 七、构建扩展包

每次改完代码，都要执行构建来生成最新的扩展包。构建前，记得在 `extension.json` 里顺手改一下版本号，然后：

```powershell
npm run build
```

构建出的扩展包会生成在 `/build/dist/` 目录下（`.eext` 文件）。

> 构建时会读取根目录下的 `.edaignore`，它控制哪些内容被排除在包外，语法和 `.gitignore` 一致。

---

## 八、导入扩展

把上一步生成的 `.eext` 文件导入 EDA 即可：

- **专业版 V2**：顶部菜单栏 → 设置 → 扩展 → 扩展管理器… → 导入扩展
- **专业版 V3**：顶部菜单栏 → 高级 → 扩展管理器… → 导入

---

## 九、几点建议

1. **善用官方案例**：嘉立创在 [github.com/easyeda](https://github.com/easyeda) 提供了大量扩展源码，在 [jlc-ext.com](https://jlc-ext.com/) 有扩展广场，先看别人怎么写的，比从空白开始快得多。

2. **路径别带空格**：这是新手最容易踩的坑，路径里有空格或中文，构建脚本可能莫名其妙报错。

3. **构建前记得改版本号**：语义化版本管理是好习惯，别每次都用 `1.0.0` 覆盖。

4. **网络问题有解**：NPM 慢走国内镜像，git 拉不动走 Gitee，别卡在网络这一关。

---

## 写在最后

写嘉立创插件这件事，门槛其实不高：会一点 JavaScript、搭好环境、看懂 `extension.json`，就能跑通第一个插件。真正值得琢磨的，是你能用它把哪些重复劳动自动化掉。

工具的意义，在于把我们从繁琐里解放出来，去做更有创造性的设计。
